# 第 6 章 控制方案选型

**这一章是全文最重要的部分。** 前面讲了问题和模型，现在要回答：**为什么选这个控制方案，而不是别的？**

我们先把问题定义清楚，然后**逐个方案对比**，每个方案都回答三个问题：

1. 它是什么（讲给没学过控制的人听）
2. 它能不能解决我们的问题
3. 它的优点和缺点分别是什么

## 6.1 先把问题定义清楚

在选方案之前，必须把"要解决什么问题"写得非常具体。**选错方案，通常是因为问题没定义清楚。**

### 被控对象

一个 7 阶非线性系统，状态 `[V, γ, α, q, h, T, δ_e]`，两个输入 `[δ_e指令, 油门指令]`。

### 控制目标

| 目标 | 指标 |
|---|---|
| 高度跟踪 | 在 0.05 ~ 0.50 m 内跟踪指令，误差 < 5 cm，**绝不触地** |
| 速度跟踪 | 保持 18 m/s，误差 < 1 m/s |
| 姿态稳定 | 俯仰角速度不振荡发散 |
| 安全 | 升降舵不长期饱和 |

### 困难清单（按严重程度排）

| 编号 | 困难 | 严重程度 | 为什么难 |
|---|---|---|---|
| D1 | **模型不确定且随状态变化** | ★★★★★ | 气动参数随 (α, q, h) 非线性变化，误差 ±40% |
| D2 | **对象本身不稳定** | ★★★★☆ | 浮沉模态 ζ ≈ -0.8，高度静稳定为负 |
| D3 | **执行器有滞后和饱和** | ★★★☆☆ | 舵机 0.05 s、限幅 ±25° |
| D4 | 多变量耦合 | ★★★☆☆ | 升降舵既影响俯仰又影响速度；油门既影响速度又影响高度 |
| D5 | 测量有噪声 | ★★☆☆☆ | 高度雷达、空速管都有噪声 |
| D6 | 外部扰动 | ★★☆☆☆ | 阵风、大气湍流 |

**D1 是决定性的**。我们后面所有的方案比较，核心都围绕"谁能对付 D1"。

### 关键判断：D1 是"参数不确定"还是"函数不确定"？

这个区分极其重要：

- **参数不确定**：真实模型是 `L = q·S·a·α`，但 `a` 的真实值我不知道。**结构已知，只是系数未知。**
- **函数不确定**：真实模型是 `L = q·S·f(α, h)`，其中 `f` 的形式我根本不知道（比如 RAM 效应）。

**本工程是后者**。因为：

1. 地效因子 κ(h) 的真实函数形式与我的估算式不同
2. RAM 效应在名义模型里**根本不存在**
3. 失速软化是非线性的

**这个判断直接决定了后面所有方案的选择**。记住它。

## 6.2 方案一：PID 控制

### 是什么

最经典的控制方法。三个环节：

```
u = Kp·e + Ki·∫e dt + Kd·de/dt
```

- **P（比例）**：误差大就使劲修
- **I（积分）**：误差持续存在就持续加力，最终消除稳态误差
- **D（微分）**：误差变化快就提前刹车，抑制振荡

**机械类比**：就像汽车定速巡航——实际速度低于设定就多给油。

### 用到本工程会怎样

要控制高度和速度两个量，用两个 PID：

```
油门 = PID(速度误差)
升降舵 = PID(高度误差)   或   PID(俯仰角误差)
```

### 优点

- 极其简单，不需要模型
- 参数少，现场好调
- 工程师都会，可靠性有保证
- 对小幅度的参数变化有一定容忍度

### 缺点（逐条对照困难清单）

| 困难 | PID 能否解决 | 说明 |
|---|---|---|
| D1 模型不确定 | **× 完全不能** | PID 不知道模型，无法"补偿"模型误差 |
| D2 对象不稳定 | △ 勉强 | 只要增益够大就能稳定，但相位裕度会很小 |
| D3 执行器饱和 | × | 需要额外加抗积分饱和 |
| D4 多变量耦合 | △ | 需要解耦网络，且解耦是近似的 |
| D5 噪声 | × | 微分项会放大噪声 |
| D6 扰动 | △ | 积分项最终能消除常值扰动，但对时变扰动响应慢 |

**致命问题**：本工程的高度不稳定是**对象内在的**（`∂M/∂h > 0`），PID 必须靠"增益够大"来硬压。但增益一大，遇上官滞后（0.05 s 舵机 + 0.1 s 滤波）就会振荡发散。

**试验数据**：本工程实际试过 PID 结构（就是代码里的 "纯动态逆" 对照组的简化版），结果是**触地**。

### 结论

**× 不采用。** 不是 PID 不好，而是它对付不了"结构和参数都未知"的对象。

## 6.3 方案二：增益调度 PID

### 是什么

既然一套 PID 参数不够用，那就按飞行状态**准备多套参数**，飞行中查表切换：

```
if h < 0.15
    用第一套参数
else
    用第二套参数
```

航空发动机和很多民机飞控都用这个思路（叫**增益调度**，Gain Scheduling）。

### 优点

- 保留了 PID 的所有优点（简单、可解释）
- 能处理"参数随状态变化"的问题
- 工程上极其成熟，适航认证友好

### 缺点

| 问题 | 说明 |
|---|---|
| **需要预先知道变化规律** | 要设计调度表，必须先知道"每个高度该用什么参数"——但 D1 说的正是"我们不知道" |
| **维度爆炸** | 如果参数随 h、V、α 三个变量变化，三维调度表就要做大量试验 |
| **切换不连续** | 参数切换瞬间可能产生跳变，需要额外的平滑处理 |
| **无法处理"模型里没有的效应"** | RAM 效应在我们的名义模型里不存在，调度表里也就没有对应项 |

**最致命的一点**：增益调度本质上是**开环补偿**——它假设"我提前知道每种情况该怎么办"。而本工程的核心困难是"我不知道真实的气动是什么样"。**用一个不知道的东西去补偿另一个不知道的东西，是不成立的。**

### 结论

**× 不采用**（但可以作为基础方案的一部分——本工程实际上用了类似的思想做初始参数整定）。

## 6.4 方案三：LQR / 极点配置

### 是什么

基于线性模型 `dx/dt = A·x + B·u`，设计**全状态反馈**：

```
u = -K·x
```

- **极点配置**：指定闭环特征值应该在哪
- **LQR（线性二次型最优控制）**：最小化 `∫(x^TQx + u^TRu)dt`，Q 和 R 是权重矩阵

**LQR 的优点**：有严格的数学保证（保证稳定、有一定鲁棒性），能自动处理多变量耦合（D4）。

### 优点

- 数学上最优，有保证
- 天然处理多变量
- 只需解一个代数黎卡提方程，计算量小
- 对**参数在小范围内变化**有鲁棒性

### 缺点

| 问题 | 说明 |
|---|---|
| **必须线性化** | 在某个配平点线性化，偏离就失效 |
| **参数变化大就失效** | 本工程气动参数变化 ±40%，LQR 的"鲁棒性"覆盖不了 |
| **不能处理未建模动态** | RAM 效应不在 A、B 矩阵里，LQR 视而不见 |
| **需要全状态反馈** | α、q 等状态需要测量或估计 |

**本工程的实测情形**：在 h = 0.20 m 配平点设计的 LQR，拿到 h = 0.05 m 或 0.50 m 就性能骤降——**因为 A、B 矩阵整个变了**。

### 结论

**× 单独使用不采用。** 但**可以作为一个"基线控制器"**——事实上第 6.5 节的动态逆比 LQR 更适合做基线，因为动态逆能直接利用非线性模型。

## 6.5 方案四：动态逆（NDI，Nonlinear Dynamic Inversion）

### 是什么

**核心思想一句话**：我知道模型，那就**用模型反解出"该给什么控制量"**。

假设模型是：

```
dq/dt = f(x) + b·δ_e
```

我希望角加速度等于某个我想要的值 ν，那就解方程：

```
ν = f(x) + b·δ_e
=>  δ_e = (ν - f(x)) / b
```

**这就是"反解"**。像解代数方程一样简单。

**机械类比**：你要让一个质量块以加速度 a 运动，需要多少力？`F = m·a`。这就是最基本的动态逆。

### 优点

- **概念最清晰**：想要什么动态，就反解出控制量
- **充分利用非线性模型**：不需要在工作点线性化
- **天然解耦**：可以分别设计俯仰通道、速度通道
- **可以精确指定闭环动态**：想让俯仰回路像一阶惯性？直接把 ν 定义成一阶惯性就行

### 缺点（这是关键）

| 问题 | 说明 |
|---|---|
| **完全依赖模型精度** | 模型错了，反解出来的控制量就错了 |
| **需要精确的 f 和 b** | 而本工程恰恰不知道 f |
| **不能处理未建模动态** | RAM 效应不在 f 里 |
| **对操纵导数 b 的符号很敏感** | 如果 b 很小或符号反了，控制量会爆掉 |

**用数字说明 D1 的杀伤力**：

在 h = 0.20 m 处，真实对象与名义模型的俯仰力矩差约 0.87 N·m。而升降舵的操纵能力是：

```
∂M/∂δ_e ≈ -45 N·m/rad
```

**光靠操纵能力去"压"这个 0.87 N·m 的误差，需要 0.019 rad = 1.1° 的舵偏。**

看起来不多。但高度机动过程中这个误差会持续变化，控制器如果不知道它的存在，就会产生持续的姿态误差 -> 高度误差累积。

**本工程的实测结果**（第 10 章）：纯动态逆方案的**高度误差 RMS 是 0.21 m**，而且最终**触地**。

### 结论

**△ 作为基线方案采用，但不能单独用。**

**它的价值在于**：提供了一个"结构正确、但系数不准"的控制框架。后面的神经网络正好可以挂在这个框架上做补偿。**这就是本工程最终采用的结构。**

## 6.6 方案五：反步法（Backstepping）

### 是什么

一种**系统化的非线性控制器设计方法**，处理"级联"结构：

```
x1 的导数依赖 x2     （x2 是 x1 的"虚拟控制"）
x2 的导数依赖 x3
...
xn 的导数依赖 u
```

**做法**：从最外层开始，每一步把"下一个状态"当成虚拟控制量来设计，然后用 Lyapunov 函数逐步向里推。

**本工程的结构天然适合反步法**：

```
高度 h <- γ <- θ <- q <- δ_e
```

**每一步对应一级**。

### 优点

- **有严格的稳定性证明**（Lyapunov 方法）
- 能处理**本质非线性**的对象，不需要线性化
- 不要求"模型精确"，只要求"模型结构已知"
- 自适应和神经网络可以很方便地嵌入每一级

### 缺点

| 问题 | 说明 |
|---|---|
| **"微分爆炸"** | 每一步都要对上一级的虚拟控制量求导，级数一多表达式就爆炸 |
| **需要虚拟控制量的导数** | 而虚拟控制量往往含测量噪声，求导会放大噪声 |
| **模型结构仍需已知** | 如果 RAM 效应不在结构里，反步法也补不了 |

**"微分爆炸"有多严重**：假设有 4 级，第一级的虚拟控制量是一阶导，第二级要二阶导，第四级要四阶导。而我们的虚拟控制量里含 `arcsin`、`α` 等量——**四阶导数根本写不出来**。

### 解决方案：动态面控制（DSC）

**DSC 的核心思想**：不去解析求导，而是**让虚拟控制量通过一个一阶低通滤波器**，用滤波器的状态导数代替真实导数。

```
τ·dθ_c/dt = θ_d - θ_c
```

- `θ_d` 是"想让俯仰角去的地方"
- `θ_c` 是滤波后的实际指令
- `dθ_c/dt` 直接可以从滤波器方程里读出来，**不用解析求导**

**代价**：引入滤波器误差，需要在 Lyapunov 函数里额外加一项来证明它不影响最终结论。

### 结论

**√ 采用反步法 + DSC。** 理由：

- 我们的系统天然是级联结构（高度 -> 航迹角 -> 俯仰角 -> 角速度）
- 需要严格的稳定性证明（本工程要写报告，证明是加分项）
- DSC 解决了微分爆炸问题，实现起来只是几个一阶滤波器

## 6.7 方案六：滑模控制（SMC）

### 是什么

**核心思想**：设计一个"滑模面" `s = 0`，然后让系统**强行冲到滑模面上，并锁在上面**。

控制律：

```
u = u_等效 + η·sign(s)
```

- `u_等效`：让系统保持在滑模面上所需的控制量
- `η·sign(s)`：把系统"推"向滑模面的强力项

**优点**：

- **对匹配不确定性完全鲁棒**（理论上）
- 概念简单，实现容易
- 有限时间收敛

### 缺点

| 问题 | 说明 |
|---|---|
| **抖振（chattering）** | `sign(s)` 在 s = 0 附近疯狂切换，会让舵机来回打，实际中会损坏机构 |
| **需要知道不确定性的上界** | η 必须大于扰动幅值，但本工程不知道上界 |
| **不"学习"** | 它只是"硬扛"，不会去识别不确定性是什么 |
| **对非匹配不确定性无能为力** | RAM 效应产生的是力矩，属于匹配不确定性；但升力误差不是 |

**抖振的处理**：用 `tanh(s/Φ)` 代替 `sign(s)`，把切换变成平滑过渡。代价是**失去了完全鲁棒性**——只能保证收敛到一个边界层内。

**本工程的判断**：滑模的"硬扛"思路和我们的"学习"思路不同。而且抖振对舵机寿命不友好。

### 结论

**× 不作主方案。但它的"边界层 tanh"思想被我们**借用**到了鲁棒项设计里。**

**这是一个重要的思路**：方案选型不一定是"全都用"或"全都不用"，**好的工程方案往往是多个方法的思想组合**。

## 6.8 方案七：模型参考自适应控制（MRAC）

### 是什么

**核心思想**：指定一个"理想模型"（参考模型），让真实系统去跟踪它。

```
参考模型： dx_m/dt = A_m·x_m + B_m·r     （理想动态，我规定的）
真实系统： dx/dt = A·x + B·u
控制目标：让 x -> x_m
```

控制律：

```
u = θ_x·x + θ_r·r
```

其中 `θ_x`、`θ_r` 是**可调参数**，用自适应律在线调整：

```
dθ/dt = -Γ·e·x     （e = x - x_m 是跟踪误差，Γ 是自适应增益）
```

**这就是"自适应"的含义**：控制器参数自己会变。

### 优点

- **有严格的 Lyapunov 稳定性证明**
- 不需要事先知道真实参数
- 结构简单，计算量小
- 航空航天领域应用成熟

### 缺点（关键）

| 问题 | 说明 |
|---|---|
| **只能适应"参数"不确定性** | 它假设真实系统是 `A·x` 形式，只是 A 不知道。**但我们面对的是"函数形式未知"** |
| **参数化假设强** | 如果 RAM 效应根本不在模型结构里，MRAC 无法补偿 |
| **瞬态性能差** | 参数收敛前可能有大幅振荡（"自适应瞬态"问题） |
| **对未建模动态敏感** | 高频未建模动态会引起"参数漂移"，甚至发散 |
| **高增益时容易失稳** | 自适应增益 Γ 太大 -> 与未建模动态相互作用 -> 发散 |

### 为什么 MRAC 不够用

回到 6.1 节的关键判断：**D1 是"函数不确定"，不是"参数不确定"。**

用个具体例子说明。假设真实升力是：

```
L_真实 = q·S·[ a·α + 0.09/(1+(h/0.25)²) ]     （含 RAM 效应）
L_名义 = q·S·[ a·α ]                            （不含）
```

MRAC 的做法是：假设 `L = q·S·θ·α`，然后调 θ。但它**永远无法**用 `θ·α` 的形式逼近 `0.09/(1+(h/0.25)²)` —— 因为后者**不随 α 变化**，而前者随 α 线性变化。

**这就是"参数化不足"（parametric deficiency）。**

### 结论

**× 不作主方案。** 但它给了我们一个重要的启示：**"用自适应律在线调整"这个思路是对的，问题只在于"用什么来参数化"。**

## 6.9 方案八：L1 自适应控制

### 是什么

MRAC 的改进版。核心改动有两点：

1. **加一个状态预测器**：不只是跟踪误差，还预测状态误差
2. **加一个低通滤波器**：把自适应律的输出滤波后再送进控制量

结构：

```
u = -K·x + σ_hat 的低通滤波版本
dσ_hat/dt = Γ·Proj(σ_hat, -Δx^T·P·B)      （Δx 是预测误差）
```

### 优点

- **瞬态性能好**——低通滤波器把高频的自适应动作滤掉，避免了大振荡
- **可以显式设计"鲁棒性 vs 性能"的权衡**（通过滤波器带宽）
- 理论上有保证的瞬态界

### 缺点

| 问题 | 说明 |
|---|---|
| **滤波器带宽难选** | 带宽太高 -> 失去鲁棒性；太低 -> 补偿能力弱 |
| **实现复杂度高** | 需要状态预测器，需要设计 P 矩阵 |
| **同样需要"匹配条件"** | 不确定性必须能通过控制通道影响系统 |
| **仍然是参数化自适应** | 对"函数形式未知"的补偿能力取决于参数化基函数的选择 |

**本工程的判断**：L1 的核心价值在于瞬态性能。但本工程的瞬态问题可以通过另外的方式解决（见 6.12 节鲁棒项）。而且 L1 的参数化问题依然存在。

### 结论

**× 不作主方案**，但**它的"低通滤波"思想提醒我们注意自适应的高频动作**（这在本工程调试时确实是个问题，见第 9 章）。

## 6.10 方案九：神经网络自适应

### 是什么

**核心思想**：既然不确定性是一个**未知函数** `Δf(x)`，那就用一个**通用函数逼近器**去在线逼近它。

```
u_补偿 = W^T·φ(x)
```

- `φ(x)`：基函数（特征）
- `W`：可调权值
- 自适应律在线调整 W

### 为什么神经网络能解决"函数不确定"

**通用逼近定理**：一个足够宽的单隐层神经网络，可以在紧集上以任意精度逼近任何连续函数。

**这句话的工程含义**：不管真实的气动函数长什么样（只要是连续的），只要给我足够的节点，我就能逼近它。

**这正好解决了 MRAC 的"参数化不足"问题**：我们不再假设"不确定性 = 未知常数 × 已知函数"，而是"不确定性 = 未知函数"，然后用网络去学。

### 关键设计选择：用哪种网络

| 网络类型 | 优点 | 缺点 | 是否采用 |
|---|---|---|---|
| BP 神经网络（多层感知机） | 逼近能力强，通用 | **权值非线性出现 -> Lyapunov 证明困难**；需要反向传播，慢；**离训练区远了行为不可预测** | × |
| **RBF 神经网络** | **对权值线性 -> 证明容易**；局部支撑 -> 外推安全；训练快 | 节点数随输入维度指数增长（"维数灾难"） | **√** |
| 模糊系统 | 可解释性好，能利用专家经验 | 规则数爆炸；隶属度函数要人工设计 | △ |
| 查表 + 插值 | 最简单 | 表要预先知道；无自适应能力 | × |

### 为什么 RBF 的两个特性这么重要

**特性 1：对权值线性**

RBF 网络的输出是：

```
y = Σj wj · φj(x)
```

**对 wj 是线性的**。这意味着：

- 误差动态可以写成 `ė = -k·e + ΔW^T·φ + ε` 的形式
- 这是一个**线性**的参数误差方程
- **Lyapunov 证明变成标准流程**，交叉项可以直接对消

如果是 BP 网络，`y = f(W2·f(W1·x))`，权值非线性出现，证明难度上升一个数量级。

**特性 2：局部支撑**

```
φj(x) = exp( -‖x - cj‖² / (2σ²) )
```

这是一个**钟形函数**，在中心 cj 附近取最大值，离远了迅速衰减到零。

**工程意义**：如果飞机飞到了"训练范围之外"的地方（比如高度突然从 0.2 m 涨到 5 m），**网络输出自动趋近于零**，控制器退化为"动态逆 + 鲁棒项"——**至少不会给出错误的补偿**。

这比 BP 网络安全得多——BP 网络在训练区外会给出**任意值**。

### 缺点

| 问题 | 说明 |
|---|---|
| **维数灾难** | 输入 3 维、每维 5 个节点 = 125 个节点；输入 5 维就变成 3125 个 |
| **需要选择中心和宽度** | 这是"超参数"，选不好影响逼近精度 |
| **逼近残差不为零** | 这是为什么必须配一个鲁棒项（见 6.12） |
| **自适应增益难调** | 太快会与采样和未建模动态冲突（第 9 章会详细讲这个坑） |

### 结论

**√ 采用 RBF 神经网络作为核心补偿器。**

## 6.12 一个具体问题：为什么必须有鲁棒项

很多人会问：**既然有神经网络了，为什么还要鲁棒项？**

三个理由：

**理由 1：网络永远不能精确逼近。**

数学上，`Δf = W*^Tφ + ε`，其中 `ε` 是**逼近残差**，不可能为零。只要它不为零，误差就有一个稳态偏置。

**理由 2：有外部扰动。**

阵风、湍流、传感器噪声，这些都是网络"没学过"的东西。

**理由 3：tanh 的形状正好合适。**

```
u_r = η·tanh(e/Φ)
```

- 误差小时，`tanh(e/Φ) ≈ e/Φ`，是一个**线性增益**（提供额外阻尼）
- 误差大时，输出饱和到 `η`（提供有界的最大补偿）
- 全程**光滑可导**（不像 sign 函数会抖振）

**为什么不用 sign(e)**：会抖振。**为什么不用纯线性 Ke**：误差大时控制量会无限增大，超出执行器能力。

**tanh 是"两头都照顾到"的折中。**

### 一个重要的工程陷阱

`tanh` 在零点附近的等效增益是 `η/Φ`。**如果 Φ 取得太小，这个增益会非常大。**

本工程调试时就踩过这个坑：一开始取 Φ = 0.06，等效增益 = 1.2/0.06 = 20。**这相当于给角速度回路额外加了 20 的增益**，把相位裕度吃光了。（详见第 9 章）

**教训：鲁棒项的"边界层厚度"是一个必须仔细选的参数，不是随便填的。**

## 6.13 为什么用三层串级结构

最后回答架构问题：为什么不做成"一个控制器直接算舵面"，而要分三层？

### 三层结构

```
高度 h  --[外环]--> 航迹角 γ  --[中环]--> 俯仰角 θ  --[内环]--> 舵面 δ_e
```

### 理由 1：时间尺度分离

| 回路 | 带宽 | 时间常数 |
|---|---|---|
| 舵面（内） | 20 rad/s | 0.05 s |
| 角速度 | 6 rad/s | 0.17 s |
| 俯仰角 | 3 rad/s | 0.33 s |
| 高度（外） | 2 rad/s | 0.5 s |

内环比外环快 3~10 倍，所以**外环设计时可以认为"内环瞬间跟得上"**。这把一个高阶问题拆成了三个低阶问题。

### 理由 2：物理意义清晰

每一层都对应一个**可测量的物理量**：

- 外环管"我要去哪儿"（高度）
- 中环管"我用什么姿态去"（航迹角、俯仰角）
- 内环管"怎么把姿态摆出来"（舵面）

**出问题时好定位**：如果高度跟踪不好但俯仰角跟踪很好，问题在外环；如果俯仰角都跟不上，问题在内环。

### 理由 3：可以和"人"比较

飞行员的操作逻辑也是分层的：看到高度低了 -> 决定爬升 -> 拉杆 -> 观察姿态。**控制器用同样的结构，便于理解、便于加入飞行包线保护。**

### 对比：为什么不做单回路

| 方案 | 优点 | 缺点 |
|---|---|---|
| 单回路（直接把高度误差映射到舵面） | 结构简单 | 高阶系统，增益难调；无法分别优化快慢动态；出问题难定位 |
| **三层串级** | **每层低阶、易调；物理意义清晰；可分别加限制** | 需要设计多个滤波器；参数更多 |

**本工程的实测**：单回路方案（代码里的 `enable_alt = false` 模式）在高度机动时表现明显更差。

## 6.15 本章小结

- **问题的本质是"函数不确定"，不是"参数不确定"**——这个判断决定了所有选择。
- PID 和增益调度无法处理未知的模型结构；LQR 只在小范围内有效。
- **动态逆提供"骨架"，但它依赖模型精度**，单独用会失败。
- **反步法 + DSC 提供级联结构和 Lyapunov 证明框架**，解决了微分爆炸。
- **RBF 神经网络解决"参数化不足"**：对权值线性（证明容易）+ 局部支撑（外推安全）。
- **鲁棒项是必需的**：网络残差永远不为零。用 tanh 而不是 sign，避免抖振。
- **三层串级基于时间尺度分离**，让每层都变成低阶、易调、可解释的问题。
- 最终方案是**多个方法思想的组合**，不是单一方法。
