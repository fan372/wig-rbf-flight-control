# 第 9 章 调试踩过的坑

这一章讲**实战**。前面所有的理论，最终都要落到"代码跑不通怎么办"上。

本工程从"模型能跑"到"控制器能飞"，中间修了五个关键缺陷。**每一个都花了很长时间才找到，而且每一个都能从理论上解释清楚。**

这一章的价值在于：**你以后遇到类似症状，能快速定位。**

## 9.1 先说方法：怎么定位"仿真发散"

发散是最常见的现象，但原因可能有十几种。**关键是把问题切小。**

本工程用的排查顺序：

```
第 1 步：模型对不对？      -> 开环仿真，从配平点出发，看能不能保持不动
第 2 步：积分对不对？      -> 检查状态的有限差分和解析导数是自洽的
第 3 步：控制器对不对？    -> 单独调用控制器，看第一步输出是否合理
第 4 步：闭环哪里不稳？    -> 求闭环特征值，看哪个状态参与最多
```

**每一步都有对应的诊断脚本**（`run_00_chk.m`、`run_00_dbg.m`、`run_00_clp.m`），这些脚本后来都保留在交付里——它们是**结论的证据链**。

### 第 1 步的实际结果

开环从配平点出发，固定配平控制，跑 3 秒：

```
开环 3 s 后: gam=0.000000 deg, h=0.200000, V=18.00000
```

**完全没动**。这说明模型和积分**是对的**，问题在控制器侧。

**这一步极其重要**：如果跳过它，你会在控制器上瞎调很久，而问题可能在模型里。

### 第 2 步的实际结果

在闭环记录的第 1 秒处，比较解析导数和有限差分：

```
状态        dx(解析)        有限差分
V       -5.475369e-01    -5.473851e-01
gam      1.778160e-03     1.781670e-03
alpha    1.028920e-02     1.030273e-02
```

**吻合到 4 位有效数字**。积分没问题。

**顺带发现一个有意思的事**：一开始我以为 `dh/dt` 和 `V·sin(γ)` 对不上，差了好几倍。查了很久才明白——**我的对照脚本用的是另一组增益**，两次仿真的结果本来就不一样。**教训：比较数据时一定要确认是同一组参数。**

## 9.2 坑一：速度通道鲁棒项符号错误

### 症状

推力在几十秒内剧烈振荡并放大，最终发散。闭环极点分析（`wig_closedloop_eig.m`）显示：

```
主导极点：一个实极点越过单位圆（max|z| > 1）  <- 实部为正，发散
特征向量: T(1.000) V(0.030) IV(0.011)   <- 推力状态主导
```

**特征向量说得很清楚：推力状态 T 的幅值是 1.0，其他状态小两个数量级。说明这个失稳模式主要是"推力在振荡"。**

### 怎么发现的

用闭环极点分析（`wig_closedloop_eig.m`），并且做了**逐项开关测试**。

先说清实验基准：`run_00_clp_body.m` 里保留了一组**调试中间态增益**（`pc_hist`，即 `k_h = 3.0`、`k_hd = 0.8`、`tau_g = 0.05 s`），历史排查就是在这组基准上做的。下面是当前 `log_clp.txt` 给出的结果：

| 实验（基准 = 历史中间态增益） | max\|z\| | 主导极点 | 主导状态 |
|---|---|---|---|
| 基准（全部功能开启） | 0.99982 | s = −0.036 | **T（推力）** |
| **关闭鲁棒项** | **1.00415** | **s = +0.828** | **T（推力）** |
| 关闭速度环比例与积分 | 1.00000 | s = 0.000 | IV |
| k_h = 2, k_hd = 0.5（只改高度环） | 1.00156 | s = +0.312 | T |
| tau_th = 0.02, tau_q = 0.015（只改俯仰滤波） | 1.00004 | s = +0.007 | IV |
| tau_g = 0.02 | 0.99945 | s = −0.110 | IV |
| 推力线过质心 z_T = 0 | 0.99943 | s = −0.115 | IV |

**关键线索有两条**：

1. **只有"关闭鲁棒项"这一项把 max|z| 明确推过 1**（0.99982 → 1.00415，主导极点从 s = −0.036 变成 s = +0.828 的实极点），而且主导状态始终是**推力 T**。**鲁棒项就是元凶。**
2. **只改高度环或俯仰回路的参数（k_h/k_hd、tau_th/tau_q），极点模的变化在 1e-4 量级**——俯仰回路跟这个失稳模式基本无关。

**一个必须诚实说明的地方**：当前 `log_clp.txt` 里，基准（历史中间态增益）本身是 `max|z| = 0.99982 < 1`，**判定为稳定**。也就是说，这组增益只是"离单位圆只剩 1.8e-4"的**临界**状态，并不是一个真正越界的失稳算例。真正越界的只有"关闭鲁棒项"那一行。

这恰恰给出了一个更有说服力的结论：**这个失稳模式是由鲁棒项撑住的**——把鲁棒项拿掉，它立刻越过单位圆（+0.828）；把符号写反（等效于 `η_V/Φ_V` 变成正反馈、抵消 `k_V`），就等于从反方向把它推得更远。**症状的定性判断（推力主导、鲁棒项相关）有数据支撑；历史教程里那些具体小数（`+2.700`、`1.0136`、`1.0010`、`1.0168`）在当前的 `log_clp.txt` 里查不到**，它们来自一版已经无法复现的诊断脚本，请不要引用。

### 根因

回到第 7 章的推导。速度通道的误差动态是：

```
de_V/dt = -k_V·e_V - k_IV·I_V + (u_D - ΔD/m) + u_rV
```

**注意最后一项是 `+u_rV`。**

也就是说，鲁棒项 `u_rV = η_V·tanh(e_V/Φ_V)` 在误差动态里**以正号出现**。

如果 `e_V > 0`（飞太快），我们希望**减速**。但 `u_rV > 0` 会让 `de_V/dt` 更大——**越修越错**。

在零点附近，`tanh(x) ≈ x`，所以：

```
de_V/dt ≈ -k_V·e_V + (η_V/Φ_V)·e_V = -(k_V - η_V/Φ_V)·e_V
```

代入当时的参数 `η_V = 0.8`、`Φ_V = 0.15`：

```
η_V/Φ_V = 5.33
k_V = 1.2
k_V - η_V/Φ_V = 1.2 - 5.33 = -4.13    <- 负的！发散！
```

**这就是那个实极点越过单位圆的来源**：误差反馈的等效增益被鲁棒项抵消成了负的，`de_V/dt = +4.13·e_V` 是一个纯正反馈——**在连续域看，它就是一个右半平面的实极点**。

### 修复

控制律里把鲁棒项写成**减号**：

```matlab
% 错误
T_cmd = (m*(dV_des + uD + urV) + Dnom + gff) / ca;

% 正确
T_cmd = (m*(dV_des + uD - urV) + Dnom + gff) / ca;
```

改完后 `k_V - η_V/Φ_V` 重新变正，实极点回到左半平面。（此时闭环里还剩一个 10 rad/s 量级的复极点对没完全压住——`log_clp.txt` 里历史中间态增益的 s = −0.419 ± 8.052i 就是它——那是后面 9.4、9.5 两个坑要处理的。当前 `log_clp.txt` 的敏感性测试里，"关闭鲁棒项"会让这个推力主导的模式明确越过单位圆，`max|z| = 1.00415`、主导极点 s = +0.828，可以作为这条因果链的直接证据。）

### 为什么这个错误这么隐蔽

**因为俯仰通道的符号是对的。**

```
力矩通道：δ_e = (ν - f0 - uM - ur)/b
          -> dq/dt = ν + Δf - uM - ur
          -> 误差动态里是 -ur  √ 正确
```

两个通道的推导过程看起来一模一样，但符号**恰好相反**。原因是估计量在控制律里的位置不同：

- 力矩通道：`- uM`（减号）-> 自适应律用 `+Γφe`
- 速度通道：`+ uD`（加号）-> 自适应律用 `-Γφe`，鲁棒项用 `-urV`

**教训**：

> **推导控制律时，每一步都要把符号写出来，不要靠"感觉应该是对的"。**
> 尤其当两个通道结构相似时，一定要分别推一遍。

### 怎么避免

在代码里把两个通道的推导**写成并列的注释**，让差异一眼可见：

```matlab
% 力矩通道： de = (nu - f0 - uM ...)/b ，uM 以"减号"进入 => W1dot = +Gam1*phi1*e_q
% 速度通道： T*cos = m*(dVdes + uD) + ... ，uD 以"加号"进入 => W2dot = -Gam2*phi2*e_V
```

## 9.3 坑二：自适应增益与回归向量量纲不匹配

### 症状

修好符号后，出现了新的现象：**权值在几个采样周期内就冲到投影上界**（`W_max = 12.0`），升降舵瞬间饱和到 ±25°，飞机在 1 秒内失控。

```
t=0.0   de=-3.60°  W1norm=0.000
t=0.1   de=-25.0°  W1norm≈12（已贴投影上界）
```

**20 个采样周期（0.1 s），权值就从 0 涨到上界，舵打到满偏。**

### 根因

第 7.7 节讲过，回归向量被缩放了 `q∞Sc/I_yy ≈ 66.265` 倍（平方约 4391）：

```matlab
phi1 = ph1r * (qbar * p.S * p.c / p.Iyy);   % 乘了约 66，平方后约 4391
```

而自适应律是：

```matlab
W1 = W1 + Ts * Gam1 * phi1 * e_q;
```

代入 `Ts = 0.005`、`Gam1 = 45`、`phi1 ~ 66·φ`：

```
每个采样周期的权值增量 ≈ 0.005 × 45 × 66 × φ × e_q
                      = 14.85 × φ × e_q
```

如果 `e_q ~ 0.01`（很小的误差），`φ ~ 0.3`，则增量 ≈ 0.045。看起来不多。但**误差会自我放大**：

权值增大 -> 补偿量 `uM` 增大 -> 过度补偿 -> 误差反向增大 -> 权值继续增大……

**这是一个增益过大导致的正反馈。** 而且它是**指数**的：每个周期乘一个大于 1 的因子，20 个周期就足以把 0 推到 12。

用第 7.12 节的判据（配平点 V = 18 m/s、h = 0.20 m，`k_q = 6.00`）：

```
T_s·Γ1·‖φ1‖² = 0.005 × 45 × 2.369e4 ≈ 5328     >>  k_q = 6
```

**超出判据约 890 倍**（早期教程里这里写的是 `≈ 196 >> 2`，那个数来自一条**错误的判据**：它漏掉了该通道的比例增益 `k_q`，而且把 `‖φ_rbf‖²` 估成了 2，实际配平点是 5.39。详见 7.12 节的更正说明）。

### 修复

把 `Gam1` 从 45 降到 **0.005**，再代回**正确的判据**：

```
T_s·Γ1·‖φ1‖² = 0.005 × 0.005 × 2.369e4 = 0.5922  <  k_q = 6.00   √
无量纲裕度比：k_q / (T_s·Γ1·‖φ1‖²) = 10.1
```

### 教训

> **自适应增益不能凭感觉给。**
> 必须用 `T_s·Γ_i·‖φ_i‖² / k_i` 这个**无量纲比值**来判断，它必须远小于 1。
>
> **注意 `φ_i` 包含了"回归向量的缩放因子"，而且判据里是它的平方。** 同样一个 Γ，回归向量放大 10 倍，有效推进量就放大 100 倍。

### 为什么两个通道的增益数字差这么多

| 通道 | Γ | 缩放因子 g | 看起来差 |
|---|---|---|---|
| 力矩 | 0.005 | 66.265 s^-2 | |
| 阻力 | 3.0 | 1/12 = 0.0833 kg^-1 | |

看起来差 600 倍。但这只是因为回归向量的量纲不同——**力矩通道的回归向量带 `1/s²` 的量纲，阻力通道带 `1/kg`**，而缩放因子本身差了 `66.265 / 0.08333 ≈ 795` 倍。

**不要直接比较两个通道的 Γ 数值大小**，要比较无量纲比值 `T_s·Γ_i·‖φ_i‖² / k_i`：力矩通道 0.0987，阻力通道 3.66e-4，**两者都远小于 1**。也不能拿 `Γ·g²`（力矩 21.8、阻力 0.0207，差三个数量级）来比——那个量本身不具备跨通道可比性，因为两个通道的误差量纲（rad/s 与 m/s）和比例增益都不一样。

### 一个附加发现

排查过程中还发现：**量测滤波器的欧拉实现也有同样的约束。**

```matlab
ctrl.xf = ctrl.xf + (Ts_/tau_f) * (xm - ctrl.xf);
```

如果 `tau_f` 太小（比如 1e-4 而 Ts = 0.005），`Ts/tau_f = 50 > 2`，这个滤波器**本身就会发散**。测试时把 `tau_f` 设成 1e-4，闭环极点模直接冲到 49.26。

**修复**：`tau_f` 设成 0.02，`Ts/tau_f = 0.25` √

**这是同一个数学约束在不同地方的表现**：`Ts/τ < 2`。

## 9.4 坑三：鲁棒项边界层过薄

### 症状

符号和增益都修好后，闭环里仍残留一个高频振荡在缓慢发散。当时的诊断输出是：

```
max|z| = 1.0031    主导极点 s = +0.61 ± 6.54i
特征向量: T(1.000) q_cf(0.126) q(0.108)
```

频率 6.5 rad/s 的振荡，缓慢发散。特征向量里 `T` 仍然是最大分量（1.000），但 `q_cf`（0.126）和 `q`（0.108）比 9.2 节那个纯推力模式明显抬高了——**说明这一次俯仰回路也参与进来了，不再是"纯推力问题"**。这就是把范围从速度通道扩展到鲁棒项边界层的依据。

> 说明：上面这组小数（1.0031、+0.61±6.54i）属于**当时的诊断记录**，当前 `results/log_clp.txt` 里已经没有这一行；能直接引用的是同一套脚本给出的"关闭鲁棒项 → max|z| = 1.00415、主导极点 s = +0.828"（见 9.2 节）。定性结论（鲁棒项参数不当会把这个模式推到单位圆外）两者一致。

### 怎么发现的

做**参数扫描**，发现结果对 `Φ_r`（力矩通道边界层厚度）**极其敏感**：

| η_r | Φ_r | 等效增益 | 结果 |
|---|---|---|---|
| 2.5 | 0.40 | 6.2 | 触地 |
| **2.5** | **0.80** | **3.1** | **稳定** |
| 2.5 | 1.50 | 1.7 | 触地 |
| 4.0 | 0.80 | 5.0 | 触地 |
| 6.0 | 2.50 | 2.4 | 稳定 |

**注意第二列和最后一列**：`Φ_r = 0.8` 时稳定，`Φ_r = 1.5` 时又不稳定了。这说明存在一个**最优的中间值**——太小或太大都不行。

### 根因

`tanh(e/Φ)` 在零点附近的等效增益是 `η/Φ`。

- **Φ 太小** -> 等效增益巨大 -> 相当于给该回路额外加了很大的比例增益 -> **吃掉相位裕度** -> 高频振荡
- **Φ 太大** -> tanh 大部分时间工作在线性区 -> 鲁棒项退化为普通比例项 -> **失去"有界补偿"的作用**（不再是"最多补 η 那么多"）

用相位裕度算一下。当时的俯仰角速度回路：

```
k_q = 6，鲁棒项等效增益 = η_r/Φ_r = 1.2/0.06 = 20
总等效比例增益 = 6 + 20 = 26
```

回路的主要滞后：

- 舵机 0.05 s
- 角速度滤波器 0.047 s
- 采样 0.005 s
- 合计约 0.10 s

在 6.5 rad/s 处，滞后贡献的相位：

```
0.10 × 6.5 = 0.65 rad = 37°
```

而 `k_q = 26` 意味着回路穿越频率约 26 rad/s？不对——实际穿越频率受滞后限制。用二阶近似 `τ·d²q/dt² + dq/dt + K·q = 0`（τ 是总滞后）：

```
特征方程：τ·λ² + λ + K = 0
阻尼比：ζ = 1/(2√(τ·K)) = 1/(2√(0.10×26)) = 1/3.22 = 0.31
```

`ζ = 0.31` 对应的相位裕度约 33°——**本来就紧张**，再叠加其他滞后就发散了。

如果 `Φ_r = 0.8`，等效增益 3.1，总增益 9.1：

```
ζ = 1/(2√(0.10×9.1)) = 1/1.91 = 0.52     √ 健康
```

### 修复

```matlab
p.ctrl.eta_r = 2.50;      % 鲁棒增益
p.ctrl.Phi_r = 0.80;      % 边界层（等效增益 3.1）
p.ctrl.eta_V = 1.50;
p.ctrl.Phi_V = 1.00;      % 等效增益 1.5
```

### 教训

> **鲁棒项的"边界层厚度"是一个必须仔细选的参数。**
>
> **经验法则**：`η/Φ`（零点等效增益）**不应超过该回路比例增益的量级**。
> 本工程最终 `η_r/Φ_r = 3.1`，与 `k_q = 6` 同量级 √

这个坑在文献里很少被强调，因为理论分析通常只关心"η 要足够大"，不关心"η/Φ 会带来额外增益"。**但工程上这一条至关重要。**

## 9.5 坑四：推力重力前馈构成正反馈

### 症状

排查完前三个坑，闭环仍有一个 6.5 rad/s 的模态在缓慢发散。对它的特征向量做**相量核验**：

按特征向量各分量代入 `δT_cmd` 的线性化表达式，逐项算贡献：

```
-mg·δγ 项:      1.036 ∠-140°     <- 最大的一项
-k_V·δV 项:    -0.430 ∠28°
urV 项:        -0.380 ∠28°
Dnom 项:        0.30  ∠-55°
合计:           1.485 ∠223°
理论要求:       1.468 ∠222°
```

**吻合到 1%。** 这说明这个模态确实是真实的，而且**主要驱动项是 `m·g·sin(γ)` 这一项**。

### 根因

速度回路的推力指令里有重力前馈：

```matlab
T_cmd = (m*(dV_des + uD - urV) + Dnom + m*g*sin(gam)) / ca;
                                        ^^^^^^^^^^^^^^
```

**这一项的物理意义是对的**（爬升时需要额外推力克服重力分量），但它取自**实测的 γ**，于是形成了一条正反馈回路：

```
γ 增大
  -> T_cmd 增大（因为 sin γ 变大）
  -> 推力增大
  -> 速度增大
  -> 升力增大（L 正比于 V²）
  -> dγ/dt 增大
  -> γ 进一步增大        ← 回到起点，而且放大了
```

**这条回路的增益是 `m·g = 117.7 N/rad`**，非常大。

用频域看：`γ` 到 `T_cmd` 的增益是 117.7 N/rad，而发动机的滞后只有 0.15 s。在 6.5 rad/s 处，0.15 s 滞后贡献 `0.15×6.5 = 0.98 rad = 56°` 相位滞后——**足以把这条正反馈变成发散振荡。**

### 修复

改成用**指令航迹角**做前馈：

```matlab
gff = p.m * p.g * sin(ctrl.gam_c);      % 用指令值，不用实测值
T_cmd = (p.m * (dV_des + uD - urV) + Dnom + gff) / ca;
```

`γ_c` 是指令，不受飞机实际状态影响，**回路被切断**。

**残余误差怎么办**：如果实际 γ 和 γ_c 有差，重力补偿会有偏差。但这个偏差会被速度环的积分项 `k_IV` 消除——**用积分项处理缓慢的模型误差，是标准做法**。

### 教训

> **前馈项的输入必须来自"指令"，不能来自"量测"。**
>
> 前馈的目的是"提前补偿已知的确定性影响"，如果它的输入带反馈，就变成了一个**额外的高增益反馈回路**，而且往往没经过稳定性设计。

**这是一个非常通用的原则**，在机器人、电机控制里同样适用。

## 9.6 坑五：航迹指令滤波时间常数过大

### 症状

高度环的相位裕度不足，高度响应有明显振荡。

### 根因

`τ_g`（航迹角指令滤波器）最初取 **0.20 s**。

回顾第 2.8 节的结论：**滞后是相位裕度的杀手。**

高度环的总滞后：

| 环节 | 时间常数 |
|---|---|
| 航迹角指令滤波 | 0.20 s |
| 俯仰角指令滤波 | 0.10 s |
| 角速度指令滤波 | 0.047 s |
| 舵机 | 0.05 s |
| 迎角-航迹角动力学 | 约 0.25 s |
| **合计** | **约 0.65 s** |

高度环的设计带宽是 1~2 rad/s。在 1.5 rad/s 处，总滞后贡献：

```
0.65 × 1.5 = 0.98 rad = 56°
```

再加上飞机本身高度模态的相位特性，**裕度所剩无几**。

### 修复

`τ_g` 从 0.20 降到 **0.010 s**（几乎不滤波）。

**为什么可以降到这么小**：因为上游的**参考指令二阶滤波器**（`wn_h = 1.2`）已经把指令平滑过了，航迹角指令本身就是光滑的，不需要再滤一次。

**教训**：

> **滤波器不是越多越好。每一个滤波器都在消耗相位裕度。**
>
> 设计时要问：**这个滤波器到底是为了滤什么？** 如果只是"习惯性加一个"，那就去掉。

### 顺带发现的一个细节

同一次排查还发现：俯仰角滤波器 `τ_θ` 从 0.10 减小反而**变差**了。

原因是：`τ_θ` 太小 -> 俯仰角指令变化太快 -> 等效回路增益上升 -> 相位裕度反而更紧。

**所以滤波时间常数存在一个最优值，不是"越小越好"。**

本工程最终取 `τ_θ = 0.10`、`τ_q = 0.010`，是网格搜索出来的。

## 9.7 整定流程总结

上面五个坑修完之后，做了一轮系统整定。方法值得介绍：

```
第 1 步：建立闭环极点分析工具
        （wig_closedloop_eig：把一个采样周期的映射数值线性化求特征值）

第 2 步：逐项开关测试，定位失稳源
        （改一个增益，看主导极点动没动；不动的说明不在那个回路里）

第 3 步：全包线多点网格搜索
        （在 h = 0.05/0.10/0.20/0.35/0.50 五个高度上同时评价，
          取最坏情况，避免"只在设计点稳定"）

第 4 步：非线性闭环验证
        （极点稳定 ≠ 非线性仿真稳定；最后必须用真实非线性模型验证）
```

### 第 2 步为什么有效

**如果改一个回路的增益，主导极点完全不动，那这个极点一定不在那个回路里。**

这是**结构性推理**，比反复试参数高效得多。本工程正是靠这一步把范围从"整机"缩小到"速度通道鲁棒项"。

### 第 3 步为什么要多点

只在一个工作点稳定是不够的。本工程一开始的整定结果：

```
truth h=0.20 m  max|z| = 0.99870   √ 稳定
truth h=0.05 m  max|z| = 1.00447   × 发散
truth h=0.50 m  max|z| = 1.00387   × 发散
```

**设计点稳定，包线两端发散** —— 这就是为什么必须做多点优化，取最坏情况。

> 说明：上面这三个 `max|z|` 是当时那一版脚本的输出，当前 `log_clp.txt` 只评价 h = 0.20 m 一个平衡点（以及一组单点敏感性测试），**查不到 0.99870 / 1.00447 / 1.00387 这三个数**。要复现"包线两端更差"这个结论，需要在 `wig_closedloop_eig` 上分别在 h = 0.05 / 0.20 / 0.50 m 配平并各自求解平衡点——这是本工程下一步要补的工作。**结论的方向（低空地效最强、高度静稳定性最差）在第 5 章的逐高度扫描里有直接支撑**：h = 0.05 m 处 `∂M/∂h = +14.901 N·m/m`，是 h = 1.00 m 处（+1.056）的 14 倍。

### 第 4 步为什么必须做

极点分析用的是**冻结参数 + 线性化**，它假设：

- 权值不变（冻结）
- 系统在平衡点附近（线性化）
- 没有饱和（线性）

而真实的非线性仿真里，权值在变、飞机在大范围机动、舵可能饱和。

**所以极点稳定只是必要条件，不是充分条件。最终必须用非线性仿真确认。**

### 整定前后的闭环极点对比（`log_clp.txt`）

`results/log_clp.txt` 现在同时给出两组增益的评价结果，这是这一节最直接的证据：

| 增益组 | 参数 | max\|z\| | 主导状态 | 结论 |
|---|---|---|---|---|
| **出厂增益（shipped `wig_params()`）** | k_h = 2.00、k_hd = 0.80、tau_g = 0.010 s | **0.99942** | IV | **稳定**，最慢模态 s = −0.116 s^-1 |
| 调试中间态（历史，`pc_hist`） | k_h = 3.0、k_hd = 0.8、tau_g = 0.05 s | **0.99982** | T | 也稳定，但只剩 1.8e-4 的余量 |
| 历史中间态 + **关闭鲁棒项** | 同上，`enable_rob = false` | **1.00415** | T | **失稳**，s = +0.828 |

**怎么读这张表**（这一点很重要，请按数据本身读，不要按"故事应该怎样"读）：

- **出厂增益确实稳定**：`max|z| = 0.99942 < 1`，而且是在**真正的闭环平衡点**上评价的（平衡点求解残差 6.6e-17，即机器精度），不是在配平点附近草草线性化。所以这个结论可以直接引用。
- **历史中间态增益也是稳定的**（0.99982），不是失稳。它和出厂增益的差别只有 4e-4 量级，两者都紧贴单位圆。
- **这一节里唯一真正越界的算例是"关闭鲁棒项"**（1.00415）。也就是说，**失稳不是某一组增益"调坏了"，而是鲁棒项一旦缺失就会发生**——这正是 9.2 节那个符号错误的另一种表现方式。

注意"稳定"不等于"裕度大"：`max|z| = 0.99942` 离单位圆只有 5.8e-4，最慢模态（积分器 IV 主导）的时间常数约 8.6 s。**这说明这个设计是"够用但不宽裕"**——这正是第 10 章里阵风工况会把飞机打到触地的原因，也说明为什么下一步工作要做增益调度或更强的自适应。

（历史教程在这里写过"设计点 max|z| = 0.99870 稳定、包线两端 1.00447 / 1.00387 发散"这样一组数。那组数同样来自已经无法复现的旧诊断脚本，在当前 `log_clp.txt` 里**一个都查不到**；"必须多点整定、取最坏情况"这个结论依然成立，但请不要引用那三个小数。）

|---|---|---|---|---|

## 9.9 三条通用经验

把五个坑抽象成三条：

### 经验 1：先验证模型，再怀疑控制器

**方法**：开环从配平点出发，看能不能保持不动。如果能保持，模型和积分就是对的。

**为什么重要**：本工程 90% 的调试时间都在控制器侧，如果一开始就怀疑控制器而不验证模型，会走很多弯路。

### 经验 2：用"结构性推理"缩小范围，而不是盲目试参数

**方法**：改变一个参数，看效果变不变。不变就说明问题不在这里。

**为什么有效**：参数空间太大，穷举不可能。而"改 A 不影响 B"这个信息能快速排除整个回路。

### 经验 3：把每个坑写成"症状 -> 判据 -> 修复"的条目

**为什么**：下次遇到同样的症状，直接查表。**经验的价值在于可复用，而可复用需要被记录下来。**

本工程所有的诊断脚本都保留在 `src/run_00_*.m` 里，就是出于这个目的。
